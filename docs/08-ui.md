# 8. UI: menu entry, connect window, lobby

The UI is built from Spore's own window system (UTFWin), with no external overlays.
Buttons, frames, fonts and icons are the game's own objects, so the window looks native
and handles mouse and keyboard the same way as every other Spore window.

## 8.1 What the player sees

* **Main menu**: below "Galactic Adventures" there is a **Co-op** entry with its own icon
  (two players). It is a copy of the "Share" button: same style, its own icon from
  `Data/SporeCoop.package`.
* **Co-op window** (frame, logo and close button come from Spore's account window). Since 0.7.12 the connect page
  is split into steps (name, Host / Join, Host, Join) and the lobby has a Settings page: see
  [the window in steps](#ui-window-steps); the list below is the 0.7.11 window:
  * "Your name" - nickname (saved to `mods/coop.ini`);
  * "Join a friend's game" - an `ip:port` address and a **Join** button (Enter in the field also connects);
  * "Games on your network" - games found on the local network (host name, stage, world,
    player count, address); click one to connect;
  * "Host a game" - UDP port and a **Host** button; below it, the addresses to give your friends.
* **Lobby** (the same window once a game is hosted or you have joined):
  * session line ("Hosting on UDP port 47810 - 2/4 players" / "Connected to Alice (…)");
  * player table: name (host, "you"), stage and "other world", ping, ready state;
  * world line: "Receiving Alice's world: 45%", "Load or start a game…"; a host alone in a menu reads "Start or
    load a game now: friends can join any time", a host alone in its world "Nobody has joined yet: friends who join
    get your world by themselves" (BUG-0597, `core.ui_share_explain`);
  * creation row: "My creature: Kirgle  (in My Creations: 3)  < >" switches the own creation; without own creations of
    that kind it reads "My creature: the host's species (make one in an editor to pick it)" with no arrows (the host:
    "your world's species", a ship: "your empire's ship"; BUG-0598, `core.ui_creation_hint`). With no arrows and no
    give / jump buttons the row takes their room (up to x 720);
  * chat (4 lines, long lines wrapped, the arrows on the right scroll through the last 50 lines;
    Enter sends), join and leave events;
  * buttons **I'm ready / Not ready**, **Send my world** (host, resend the world to everyone; greyed out, the
    window flag `kFlagEnabled` off, while no world is loaded or nobody has joined, and a click that still reaches it
    says why instead of "Sending the world to everyone...", BUG-0597), **Leave / Stop hosting**.
  * Text widths: the dialog font is ~9.3 px per Latin letter at 1080p (`text_width`), Cyrillic letters are wider: a
    68-letter English line fits the 680 px rows, a 66-letter Russian line wrapped (layout shots of
    `coop_ui_explain.py`, `coop.uistate lang ru|en` switches the texts set from then on for such shots). Keep new
    Russian lines under ~55 letters.
* **Space page** (Space stage only: the **Space >** button at the top right of the lobby): up to 9
  rows of the space features (`mods/coop/space_ext.h`), each a text and an optional button (for
  example "Bob: in another star system  [Jump there]"); **< Lobby** goes back. A button's action
  runs outside the frame. Tests: `coop.space rows` lists the rows, `coop.space press <n>` presses
  the button of row n, `coop.uistate` has the widgets `space`, `sbtn0..8` and `sback`.
* **F9** opens and closes the window in any mode (in game, in editors).
* Language: `[ui] lang=auto|en|ru` in `mods/coop.ini` (auto - follows the Windows language).

## 8.2 Lobby networking (protocol v4)

* `MSG_READY` (guest → host): ready flag. The host keeps everyone's flags.
* `MSG_LOBBY` (host → guests, once a second and on changes): for each player, id,
  ready state and ping as measured by the host. A guest measures its own ping to the host.
* LAN discovery: the guest sends an `SPCQ` datagram to ports 47810–47813 at
  255.255.255.255, the broadcast addresses of its networks, and 127.0.0.1. The host replies
  on its game socket with `SPCR`: name, port, players, stage and world (`net/discovery.*`,
  unit test `test_discovery`). Discovery does not work over the internet: you need the host's
  address (UDP port forwarding on the router, or a VPN such as ZeroTier / Radmin VPN / Tailscale).

## 8.3 How it works (`mods/coop/sui.*`, `mods/coop/coop_ui.*`)

* **Window tree**: `IWindowManager::Get()->GetMainWindow()`. In this build a window's child
  list is at offset `IWindow+0x38` (`+0x3C` in ModAPI), the child node is `child+4`.
  The command `coop.ui tree|find|layouts|load|btn|font|show` inspects and modifies windows.
* **Layouts**: `UILayout` (constructor `0x810050`, AddRef is the second vtable slot, the first is
  the destructor) and `UILayout::Load(key, true, 0x5B598FA)` put a layout into the main UI layer.
  The Co-op window is layout `0x34A6339E` (the account window); its own text, sign-in buttons
  and checkboxes are hidden, leaving the frame, glow, logo and close button.
  A hook on `UILayout::Load` records every loaded layout (`coop.ui layouts`).
* **Buttons**: in this build `IButton::Create` is `stdcall(int, ICoreAllocator*)` and
  returns `IWindow*` (the `IButton` interface is `Cast(0x8ED27E7A)`, located at `+0x208`).
  `Get/SetCaptionBorders` and `Get/SetCaptionOffset` take separate float arguments instead of
  structs. A new button copies from a template button its type, flags, caption colors, borders,
  outline, font and **the same drawable object** (drawable, reference-counted).
* **Clicks** arrive as `ComponentActivated` (`0x287259F6`, button ID), followed by
  `ButtonSelect`; `ButtonClick` (0x17) never arrives.
* **Labels** are buttons without a drawable, "transparent" to the mouse. They always center
  their text, so for left-aligned labels the frame width is fitted to the text length.
* **Text fields**: `ITextEdit::Create` (same as buttons), `Cast(0xCF428691)`; colors,
  text frame, max length, `SetText/GetText`: as in ModAPI.
* **Menu entry icon**: `SporeStdDrawable` (constructor `0x8309B0`, 0x160 bytes) - a
  copy of the "Share" button's drawable with its own state descriptions
  (`SporeStdDrawableImageInfo`, constructor `0x830870`, 0x98 bytes) in which the icon is
  replaced. The icon is a 62×62 PNG (white; the game tints it light blue) in the package
  `Data/SporeCoop.package`: uncompressed DBPF 3.0, built by `tools/mkpackage.py`
  (group `sporecoop`, name `coop_icon`, FNV-1 hash like `id()` in ModAPI), drawn by
  `tools/make_icons.py`.
  The copy is made anew for every galaxy menu (each visit builds a new menu): setting the copy made
  for an earlier menu on the new button hung the main thread inside `SetDrawable` after a few stage
  switches (a planet-view render waiting in DXVK, frames stopped; seen with `stack.here`). The button
  is also configured before it is added to the menu.
* **Message handlers** are `IWinProc` objects whose code lives in `sporekit.dll`
  (`SkHost::ui_winproc`). When the mod is unloaded they stay attached to the windows but do nothing,
  so hot-reloading `coop.dll` does not crash the game. The new mod instance removes the
  old windows (by its own IDs `0xC00Fxxxx`) and creates new ones.
* **Outside the frame**: creating windows, fonts and textures inside `IDirect3DDevice9::Present`
  blocks DXVK. So during the frame `coop_ui::tick()` only schedules an update via
  `SkHost::run_outside_frame` (window message `WM_SK_PUMP_OUT`). UI console commands are
  declared with the `SK_CMD_OUTSIDE_FRAME` flag.
* **"Game saved" box** ✔ (runtime 2026-10-22): every save (`kMsgSaveGame`) ends with the box "The
  game on planet <name> is saved." - window control id `0x06318E78` (flags 0x43 while shown) in
  the layer `0x05B598F7`, text label `0x01510D08`, frame child `0x05822D40`. It shows up ~1.7 s
  after the save message on an idle machine, later under CPU load. While it is up the simulation is
  paused (a cell does not move) but the frames usually keep running; sometimes it also holds the
  frames. Enter (WM_KEYDOWN VK_RETURN to the game window) confirms it; a confirmed box is hidden
  (flags 0x42) and later removed from the tree. `world.cpp` watches for it after each save
  (`box_tick`, outside the frame) and confirms it. ✔ (runtime 2026-11-05, BUG-0599) The co-op window, a direct child
  of the main window with `kFlagAlwaysInFront`, takes the mouse before the box although the box is drawn above it
  (only its check mark shows over the window): the mod's click on the box's OK (and a player's) hit the co-op window,
  the box stayed and the game stayed paused while the window was open. The window steps aside (hidden 0.6 s,
  `coop_ui::step_aside`) for the mod's click (`world.box_aside`). The click is announced to `mouse::own_click`, so the
  mod's typing into a chat line under the box goes on over it (BUG-0551, `core.ui_locked_edit_keep`); keys that come in
  the same frame as the click on the line after it (a frame held by the save) go into the line too.
* The pause menu "Options" (creature stage) is one window, control id `0x0615B50D`, loaded once and
  shown / hidden (flag 0x1 on it and its parents). The overlay's world labels (name tags, pings,
  owner tags) are drawn on top of everything, so coop.cpp hides them while this window or the
  co-op window is up (checked 5 times a second outside the frame; `coop.status` line `labels:`).

## 8.4 Notifications

Co-op events (someone joined, knockout, revive, vote, chat message) are shown as panels
on the right: a panel slides in, stays for 6–10 s and slides out; up to five panels
stack (`mods/coop/notify.cpp`) below the overlay's co-op status block. The edge color and icon
depend on the event kind: chat, join and leave give their kind; other system notices are guessed
from their (English) text. A panel takes two lines of 46 letter cells (a CJK character takes two),
cut between characters, never inside one (`mods/coop/notify_text.h`, BUG-0129). The full chat
history (50 lines) can be scrolled in the F9 window.

* A panel is an image window `IImageDrawable::AddImageWindow` (`0x8078E0`,
  `cdecl(const ResourceKey*, x, y, parent)`; the window is the size of the PNG) plus one or two labels
  in the co-op window font (`0x015A5D11`). The `toast_<kind>.png` images (560×58) are drawn by
  `tools/make_icons.py` and live in `SporeCoop.package`.
* Windows are created and moved only outside the frame (`run_outside_frame`); panels do not catch the mouse.
* The game's own event log (`cUIEventLog::ShowEvent` `0xDD8640`, `SetDescription`
  `0xDD6DF0`, event descriptions are `.prop` files with template `0x02BB7AFF!0xD84D06B1`) was evaluated
  and rejected: it looks different in every phase, in the Creature phase the text hides behind the
  minimap, and in Cell and the menu it does not exist.

`tools/tests/coop_notify.py` shows notifications in every phase and checks that the
panels are built, are on screen and do not overlap (screenshots `out/shots/notify_*.png`).

## Input only from the game window (2026-11-08, fix/w46-k2b-content)
<a id="ui-window-input"></a>

Every key, click and pointer position the mod acts on comes from the game window's own message queue
(`mouse.h`: a WH_GETMESSAGE hook on the game's main thread; BUG-0090, BUG-0145, BUG-0482, BUG-0713, class BUG-0429):
primary clicks (`clicks`, `last_click`), typed characters (`take_chars`), key presses (`key_presses`, `key_pressed`:
WM_KEYDOWN / WM_SYSKEYDOWN without the auto-repeat bit) and the last pointer move over the window (`last_move`).
Never `GetAsyncKeyState` / `GetKeyState` / `GetCursorPos` for input: they answer for the whole desktop (F9 typed in a
browser toggled the co-op window). Under background mode (test runs) `GetForegroundWindow` is hooked to answer the
game window, so a focus check through it proves nothing in a test. Test: `window_input` (SporeKit `key <vk>
elsewhere`: the physical key down, no message to the window), `SPORE_FIX_OFF=input.window` fails.

## Find each other: arrows, minimap, player colours (2026-11-08, feat/w46-partner-arrows)
<a id="ui-find-each-other"></a>

F2 of docs/plan-0.7.12.md, BUG-0764. Code: `mods/coop/find.h`, `find.cpp` (namespace `pfind`), the portable rules in
`find_core.h` (`make test`: tests/validate_tests.cpp `test_find`). Console: `coop.find [colors | color <name|0..7|none>
| map [flags] | project x y z | rivals 0|1]`.

* **Player colours**: a palette of 8 (`findx::kPalette`: yellow, blue, pink, green, orange, purple, cyan, red). The host
  keeps the table (player id -> colour) and sends it to every guest (`MSG_COLORS` 67 kind 0, reliable) on every join,
  leave and change; a newcomer gets the first free colour of the first four (join order), a leaver's colour is free
  again. A pick: `pfind::request_color(idx, &why)` (the API for the lobby, F1): the host (or a player alone) takes it at
  once; a guest sends `MSG_COLORS` kind 1 to the host, which refuses a colour another player has (the table it sends
  back is the answer either way). The pick is stored in `coop.ini [coop] color=<name>` and asked for again on the next
  join. `pfind::color_of(id)` is the ARGB every UI uses: the name tags over puppets, the Tribe / Civ owner tags, the
  arrows, the minimap marks, the galaxy map's partner tags (`spacemap::player_color`), the chat lines of the F9 window
  (`Api::chat_colors`, each line in its writer's colour). `colors_changes()` grows on every change (a lobby redraws).
* **Arrows** (inside the overlay pass, `pfind::draw_arrows`): coop.cpp `find_targets` gives the partners' positions in
  this stage: Cell, Creature and Space the puppet (cell, creature, ship), Tribe the partner's chief (else its pointer),
  Civ its pointer marker (where it plays) else its first city. A partner whose projected point is in the view gets no
  arrow (its name tag shows); else the arrow sits on the screen edge (46 px margins) on the ray from the screen centre
  towards the projected point, pointing along it. Behind the camera (`world_to_screen` fills no point when the camera
  depth is under 0.1) the farthest point in front on the way from the own avatar to the partner gives the direction
  (`walked=1` in `coop.find`). The arrow is two filled triangles (a notched head, 28 px) drawn by SporeKit's
  `overlay_tris` (since 0.3.15) over a dark outline, the label "<name>  <distance>" next to it in the same colour (an
  older SporeKit: the glyph arrow of the pings). Gated by `all.partner_arrows` (read as off in Rivals mode, the
  settings' `off_in_rivals`) and hidden with every world label under a menu or the co-op window. The galaxy map's
  edge tags (space_map.cpp) follow the same setting.
* **SporeKit `overlay_tris`** (`sdk/include/sporekit.h`, d3d9hook.cpp): n triangles in back buffer pixels, one ARGB,
  alpha blended, drawn in the overlay pass. The game's render states are captured in a state block (made once,
  released before a device Reset) and applied back after each call; it sets no shaders, `XYZRHW | DIFFUSE`, no z, no
  culling, the full viewport.
* **Minimap** (Creature, Tribe; the Cell stage has none): the game's own blips (docs/re/creature.md#creature-minimap,
  docs/re/tribe.md#tribe-minimap). Every 0.25 s outside the frame: `Minimap_MoveBlip` of the partner's key, else
  `Minimap_AddBlip` with `{argb = its colour, pos, flags 0x4}` (a small pointed mark, tinted; chosen from the looks of `find_icons`); `Minimap_RemoveBlip` when it is gone or
  `all.partner_map` is off; a new colour makes the blip anew (the tint is set when it is made). The key is the address
  of a static slot of the player in coop.dll (game keys are game object pointers, never ours). A new map (stage change,
  UI reload) forgets the old blips; the Tribe rebuild clears every blip and the next update adds ours again.
  `coop.find map` reads the blips back from the game's map (`Minimap_FindBlip`), `coop.find map <hex>` sets the icon
  flags for looks.
* Test: `tools/tests/coop_find_partners.py` (`find_partners`, `find_partners_tribe|cell|civ|space`): the colours, the
  arrow's direction against the host's real position projected by the guest's game, its pixels in the screenshot, the
  setting off live and Rivals, the minimap blips at the partners' real positions. Twins `SPORE_FIX_OFF=find.arrows`,
  `find.colors`, `find.map`.
* **Who is a target** (BUG-0939, switch `find.placed`, 2026-11-11): a partner gets an arrow, a minimap blip and a
  name at its puppet only while it is shown here (its puppet exists: a fresh in-world state of this stage and world,
  so not while it loads, is in an editor or plays another stage) and its position is a place (`findx::placed`,
  find_core.h): finite, not the zero vector (the protocol's "no position": a Tribe / Civ pointer that was never put
  on the planet reports 0 0 0), and in Creature, Tribe and Civ farther from the planet's centre than half of the own
  avatar's distance from it (the centre is where the game keeps what is in no place). Tribe: the chief, else the
  pointer when it is a place; Civ: the pointer when it is a place, else the capital. The own position follows the
  same rule (no distance text from an own pointer at 0 0 0). Off: every finite position (0.7.11: right after
  Creature -> Tribe the host drew "Dave 504 m" pointing at the planet's centre while Dave had no chief yet).

BUG-0904, BUG-0905, BUG-0908, BUG-0909 (switches `core.ui_layout`, `core.ui_give_hint`).
* ✔ The game's labels (`sui::label`, IButton without a drawable) **always center their caption** in their box. Tried on
  a label widened to 430 px (lane 2, runtime): the caption alignment (IButton vtable +0x3C) with 0, 1, 2, 4, 8, 16 and
  the button type (+0x1C) 0..5 change nothing (negative result). So a left-aligned label stays a box fitted to the
  text's width (`fit`: the box is `text_width` wide, starting at the column's x).
* ✔ Glyph advances of the dialog font (`D.font_body` 0x015A5D11) at 1440x1080, measured by drawing 12 and 4 copies of
  each glyph in one label (`coop.ui caption <win> <text>`, the ink width of the screenshot, the difference / 8):
  integer advances, e.g. `i` 6, `l` 6, `f` 7, `r s t` 8, most lower-case 10-11, `m w` 16, upper-case 10-14 (`I` 5,
  `W` 17), digits 11, space 6, `.,:;` 7, `'` 4; Cyrillic 9-18. The table is `text_width` in coop_ui.cpp (ASCII and
  U+0410..U+044F; other glyphs 11). A whole string's ink is ~2 px under the sum (side bearings). With one average
  width (9.3 px, before) the estimate was off by up to 15 px a label and the settings rows started up to 12 px apart;
  with the table they start within 1 px.
* A button's caption wraps when it needs more than its width minus ~30 px ("Settings (1 changed)": 186 px in the
  210 px button wrapped).
* The lobby's columns: Player 40, Colour 280 (the own row's ">" 318..346), **Stage 362** (was 345, BUG-0908), Ping
  540, Ready 620.
* Console: `coop.uistate widgets` lists every visible widget of the window (`widget x1 y1 x2 y2 L|B <caption width>
  '<caption>'`, screen pixels); `coop.uistate demo <address> <real port> <shown port>` (README pictures) puts a
  documentation address into the address lines and the shown port into the window's texts and the overlay head;
  `coop.ui align <win> <align> [type]`, `coop.ui area <win> x1 y1 x2 y2`, `coop.ui caption <win> <text>`:
  experiments.
* Test (`coop_ui.py`, suite `ui`): `layout_problems` (every button caption fits, no label box overlaps another
  widget with text; in the menu lobby, after a setting changed, the settings page and the F9 lobby of both games),
  `label_starts` (the settings labels' first text pixel in a screenshot within 4 px), and no give hint in the
  galaxy menu with a guest joined. FAIL with the switches off: lab 20261110-203554, 20261110-203812; PASS
  20261110-204029.
